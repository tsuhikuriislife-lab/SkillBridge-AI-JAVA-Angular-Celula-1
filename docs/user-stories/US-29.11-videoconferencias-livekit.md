# US-29.11: Videoconferencias en Tiempo Real con LiveKit SFU

**Estado:** `[✅] Terminada`

---

## 1. Descripción y Objetivo de Ingeniería

Implementar la infraestructura y experiencia de usuario para sesiones de mentoría en vivo mediante videoconferencias WebRTC de baja latencia utilizando **LiveKit Server**. La solución debe garantizar el control estricto de roles y permisos desde el backend (evitando que el frontend decida quién puede publicar audio/video), emisión de tokens JWT firmados con expiración forzada y sincronización bidireccional del estado de las reuniones mediante webhooks criptográficos.

---

## 2. Arquitectura de la Solución (Hexagonal & WebRTC)

1. **Adaptador Outbound LiveKit (`LiveKitRestAdapter`):**
   - Consume la API REST Twirp de administración de LiveKit (`RoomService`) para creación y borrado idempotente de salas.
   - Genera tokens JWT de acceso utilizando el SDK oficial `io.livekit.server.AccessToken` inyectando grants a nivel de servidor:
     - Rol Tutor/Admin (`PROVIDER`, `ADMIN`): Permisos `CanPublish(true)`, `RoomAdmin(true)`, `CanSubscribe(true)`, `CanPublishData(true)`.
     - Rol Participante (`PARTICIPANT`): Permisos restringidos `CanPublish(false)`, `RoomAdmin(false)`, `CanSubscribe(true)`.
2. **Controlador Webhook Inbound (`LiveKitWebhookController`):**
   - Endpoint `/api/webhooks/livekit` que valida la firma HMAC-SHA256 del header `Authorization` y el hash SHA-256 del cuerpo del mensaje.
   - Mapea los eventos del servidor LiveKit (`room_started`, `room_finished`, `participant_joined`, `participant_left`) hacia el caso de uso `ProcessLiveKitWebhookUseCase` para persistir la asistencia real y duración de la reunión en PostgreSQL.
3. **Capa Cliente (Angular 20 Standalone):**
   - Servicio `MeetingService` que consume endpoints REST para obtener tokens de sesión y estado de reuniones.
   - Componente `MeetingRoomComponent` basado en el SDK `livekit-client`, gestionando signals de Angular para control de tracks locales (micrófono, cámara, pantalla compartida) y rendering reactivo de participantes remotos.

## 4. Validación y Criterios de Aceptación

- **CA 6.1 (Seguridad en Tokens):** Verificada en `LiveKitTokenSecurityTest`, validando que los participantes no reciben permisos de moderación o publicación no autorizada.
- **CA 6.2 (Ciclo de Vida de Salas):** Verificada en `LiveKitRoomIntegrationTest` mediante Testcontainers asegurando creación y borrado idempotente de salas.
- **CA 6.3 (Validación de Webhooks):** Comprobado rechazo con HTTP 401 ante payloads no autenticados o firmas manipuladas.
